## 1. No background scenery on any page — my mistake

The v25.6 CSS targeted `.nexus-main::before`. `Layout.jsx` renders
`.hr-shell > .hr-main`. **The selector matched nothing**, so every page except Home
had no background at all. You were right and I was wrong; I wrote the rule from the
old stylesheet instead of checking the component.

It is now painted on `<body>` itself, so it cannot miss again regardless of wrapper
classes, with `.hr-shell` lifted above it and the sidebar made opaque. I rendered it
against the real `hr-shell / hr-main` markup at midday, evening and night this time
rather than my own mock-up.

## 2. Favourites — nothing could be added

`.fav-picker` is `position:absolute; top:160px` inside `.fav-rail`, which sets
`overflow-x:auto`. Per CSS spec, when one overflow axis is not `visible` the other
computes to `auto` — so the rail **clipped the dropdown vertically** and the options
were unreachable. The Add button and its picker now sit outside the scrolling rail.

## 3. "Is 15th August a holiday or 14th August?" → "I could not find that person"

The assistant had **no holiday intent**. `/holiday/` appeared only inside the LEAVE
branch, so the question fell through to person lookup and failed on a date.

Now: a `HOLIDAY` intent is matched *before* any person lookup, and `resolveDates()`
parses **every** date in the question, so a question naming two days answers for
both — "2026-08-15 is Independence Day. 2026-08-14 is not a holiday."

Also fixed: `how many present today` was being read as `PRESENCE` (one person)
because that test ran before `COUNT`. Reordered.

## 4. Holiday drifting to the 14th

A holiday is a whole calendar day, not an instant. Depending on how the value
arrived it could be stored as `2026-08-15T00:00Z` **or** `2026-08-14T18:30Z` — both
mean "15 August" but they sit on opposite sides of midnight.

Holidays are now pinned to UTC midnight of the intended day on write. For rows saved
before this, `POST /api/holidays/repair-dates` re-pins existing records and reports
how many it fixed. **Run it once after upgrading.**

## 5. The failing test is real, and predates me

`statusFromWorkedMinutes` returns `HALF_DAY` for 180 minutes worked against a
240-minute half-day threshold; the test expects `ABSENT`. I confirmed your original
v24 build returns `HALF_DAY` too — the test simply was never run. I have not changed
the threshold logic yet because it changes pay: someone under the half-day minimum
would move from half pay to no pay. Tell me which you want and I will make it match.
